### Task 1: Data-source refactor and `NextQueryDemo`

**Files:**
- Modify: `packages/next-query/src/core.ts`, `core.test.ts`, `NextQuery.tsx`, `index.ts`
- Create: `packages/next-query/src/Panel.tsx`, `packages/next-query/src/Demo.tsx`

**Interfaces:**
- Produces:
  - `core.ts`: `revalidateEntries(entries: Entry[], key: QueryKey | string, now: number): Entry[]`. Returns a new array. Every entry whose `tags` include `keyToTags(normalizeKey(key)).at(-1)` gets a copy with `dataUpdatedAt: now`, `runs: runs + 1`, `lastDurationMs` unchanged, and `error` removed. Other entries are returned as the same objects. The key is validated with `validateKey`.
  - `Panel.tsx`:
    ```ts
    export type Source = { getQueries(): Promise<Entry[]>; revalidateQuery(key: QueryKey): Promise<void>; revalidateAll(): Promise<void> }
    export type PanelProps = { source: Source; live: boolean; position?: 'bottom-right' | 'bottom-left'; defaultOpen?: boolean }
    export function Panel(props: PanelProps): JSX.Element | null
    ```
    `live: true` keeps today's behaviour: `router.refresh()` in a transition after an action, `load()` when it ends, and a reload on pathname change. `live: false` calls `load()` right after the action and skips the router.
  - `NextQuery.tsx` keeps `NextQuery(props: NextQueryProps)` and the dev guard, and renders `<Panel source={{ getQueries, revalidateQuery, revalidateAll }} live position={...} />`.
  - `Demo.tsx`: `NextQueryDemo(props: NextQueryDemoProps)` with `type NextQueryDemoProps = { entries: Entry[]; onRevalidate?: (key: QueryKey | null) => void; position?: 'bottom-right' | 'bottom-left'; defaultOpen?: boolean }`. `null` means Revalidate all. It keeps entries in state. The source's `getQueries` returns them, `revalidateQuery(key)` applies `revalidateEntries(entries, key, Date.now())` and calls `onRevalidate(key)`, and `revalidateAll` sets every entry's `dataUpdatedAt = now` and calls `onRevalidate(null)`. The demo has no dev guard.
  - `index.ts`: add `export { NextQueryDemo, type NextQueryDemoProps } from './Demo.js'` and `export type { Entry } from './core.js'`.

### Task 3: Guide pages (query, revalidate, keys and tags, panel), EN + ES

**Files:** `docs/content/{en,es}/{query,revalidate,keys-and-tags,panel}.mdx`

Facts must match the code (`packages/next-query/src/{query,core,Panel}.ts(x)`). Read them first.

- [ ] **Step 1: `query.mdx`**
  - Signature `query<T>(key: QueryKey, fn: () => T | Promise<T>, config?: QueryConfig): Promise<T>`.
  - `QueryConfig.revalidate`: seconds > 0, or `false` (default, keep until revalidated). Anything else throws `TypeError`.
  - The result must be JSON-serializable (`unstable_cache` stores JSON; a `Date` comes back as a string).
  - Reuse with a plain function (`const getProduct = (id: string) => query(['products', id], () => db.product(id))`).
  - Errors: not cached, recorded in the panel (dev), rethrown to your `error.tsx`. `notFound()`/`redirect()` inside `fn` pass through and are not recorded.
  - Stale-while-revalidate: after `revalidate` seconds, the next read serves the old data and refetches in the background (that's `unstable_cache`).
  - How it works: `unstable_cache` with key parts `['next-query', JSON key]` and tags from the key.
- [ ] **Step 2: `revalidate.mdx`**
  - `revalidate(key: QueryKey | string): void`, and `'products'` ≡ `['products']`.
  - Prefix semantics with a table:

    | Call | Revalidates |
    |---|---|
    | `revalidate('products')` | `['products']`, `['products', 1]`, `['products', 1, 'reviews']` |
    | `revalidate(['products', 1])` | `['products', 1]` and below, not `['products']` |

  - Where to call it: server actions and route handlers.
  - Under the hood: `revalidateTag(<deepest tag>, { expire: 0 })` on Next 15 and 16.
  - The name clash with `export const revalidate` in a page, with the `import { revalidate as revalidateQuery }` fix.
- [ ] **Step 3: `keys-and-tags.mdx`**
  - Key rules: non-empty array, strings (non-empty) or finite numbers.
  - `['products', 1]` and `['products', '1']` are different cache entries that share tags.
  - Tags: `nq`, `nq:products`, `nq:products/1`.
  - Escaping: `/` → `%2F` and `%` → `%25`, so `['a/b']` ≠ `['a', 'b']`.
  - Limits: 256 chars per tag and 128 tags per entry (so at most 127 segments); both throw `TypeError`.
  - The root tag `nq` is what "Revalidate all" uses.
- [ ] **Step 4: `panel.mdx`**
  - Mount it, and note that `position` is `'bottom-right'` (default) or `'bottom-left'`.
  - Launcher: logo, bubble with stale + error count, gradient dot when all fresh.
  - Header: counts, filter by key, sort (Updated / Status / Key), Revalidate all, Reload list (doesn't revalidate), close.
  - Cards: key, status pill (fresh lime→cyan, stale, error), freshness bar counting down (`6S LEFT`, `STALE 12S`, "never stale"), ↻ to revalidate that key.
  - Detail: Revalidate button, rows (Status, Revalidate, Updated, Reads / runs, Last run), Tags (click one to revalidate that prefix; `#nq` is the root), data as highlighted JSON (first ~16 KB) with Copy.
  - "A query shows up once it has run since the dev server started."
  - Link to `./demo`.
- [ ] **Step 5: Verify** `pnpm --filter docs test && pnpm --filter docs build`.
- [ ] **Step 6: Commit** `docs: guide pages`
